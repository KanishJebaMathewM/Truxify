# Native spatial booking query observations

Run `NODE_ENV=production LOG_LEVEL=fatal node --test backend/api/test/native/spatialMatcher.node.mjs` using Node24 and the pinned/locked `spatial-deps` runtime (repository-locked Supabase2.112.3, Axios1.20.0). Tests use actual SDK GET/filter encoding, native cancellation, actual CorridorService/DriverDispatchPipeline/ProfitabilityScorer and private HTTP Data API/OSRM fixtures with a synthetic test key. No Supabase project, actual SQL/PostGIS predicate execution, production credentials, schema/RLS changes or vehicle controls are involved. Dispatcher tests verify payload formatting/propagation, not real notification delivery.

Bounds are finite ordered geographic values; filter admission owns weight/departure before awaiting HTTP. Weight0 is honored, finite0–1e9kg. Driver earliest departure is an explicit epoch/Date/ISO observation; expiry predicate allows unbounded end times or an end at/after that departure. This does not fabricate pickup ETA or reject a driver simply because departure precedes a future window. [Raw OR filter syntax](https://supabase.com/docs/reference/javascript/or) uses only fixed column/operator text and admitted normalized ISO metadata.

Unsupported constraints, including currently unimplemented vehicleType, reject explicitly rather than silently accepting an ignored constraint; no verified vehicle-column query contract was found. Success remains an array. Only SDK error:null with200/206 and a complete admitted row array counts as an observed query; genuine empty arrays remain[]. Query errors, cancellation, malformed or contradictory results throw `SpatialQueryUnavailable` (`SPATIAL_QUERY_UNOBSERVED`) and propagate through the dispatcher instead of producing success/no-matches.

The query requests the existing13columns/PENDING/geographic predicates and50row limit. Decoded results are capped50rows/1MiB, with finite/bounded selected primitives, geographic pickup/drop coordinates, weight/expiry consistency and ordered valid windows. This is a post-decode cap, not a raw HTTP streaming-byte limit. Query uses native SDK abortSignal (default10000ms, configurable1–60000) and disables automatic GET retry; default application client lookup is lazy, not independently verified as bounded API bootstrap. Financial quote semantics remain the scorer's responsibility.

Time qualification admits nonnegative integer milliseconds, owned Date values, or calendar-valid four-digit-year ISO strings with explicit UTC/offset timezone. Missing/invalid ETA, invalid/local calendar strings and reversed windows return false; valid open/closed boundaries are inclusive, null/omitted window sides are unbounded. Conservative bbox candidates and earliest-departure checks are not road-route or actual pickup-time feasibility proofs. Row fields/output arrays are independently owned; no booking reservation, payment, SQL availability or durable notification claim is made.
