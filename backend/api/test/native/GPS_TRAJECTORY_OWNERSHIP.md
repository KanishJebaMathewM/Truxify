# Native trajectory batch ownership

Run `NODE_ENV=production LOG_LEVEL=fatal node --test backend/api/test/native/trajectoryPersistence.node.mjs` with Node24 and the exact locked test dependencies in `trajectory-deps`. Supabase SDK2.112.3 matches the backend lockfile. Tests use actual SDK HTTP/PostgREST encoding, native cancellation and private loopback Data API responses with a synthetic test key. No Supabase project, PostgreSQL execution, schema/RLS changes, production credentials, hardware or vehicle controls are used.

[Supabase insert](https://supabase.com/docs/reference/javascript/insert) returns an error result and does not return rows by default. A flush acknowledges an exact owned prefix only for error:null with an actual2xx SDK status. A rejected/aborted/network-error request returns0 and retains its prefix. This counts rows in an acknowledged insert request, not independently verified database row commits. Ambiguous response loss can duplicate rows on retry: delivery is volatile and at least once, not exactly once or crash durable. A database idempotency constraint/schema protocol would be a separate repair.

A single flight retains queue ownership through complete request settlement; append/threshold/interval/manual flush calls cannot overlap it. Capacity includes admitted rows. Defaults:50rows per batch,10000pending rows,10second interval/deadline. Configurable bounds are1–1000batch rows, capacity at least a batch/up to100000, interval up to3600000ms, request deadline up to60000ms. Overflow rejects new admission rather than evicting owned data. [Native SDK abortSignal](https://supabase.com/docs/reference/javascript/using-modifiers-abortsignal) bounds the actual HTTP request; ambient default API bootstrap is not a separately verified bounded operation.

Rows copy bounded primitive identifiers, finite geographic coordinates, speed0–10000m/s, heading0–360 and bounded nullable road text. Timestamp0 is preserved. Date values are owned; explicit UTC ISO strings are calendar-validated and fractional milliseconds normalized. Omitted timestamp records native arrival time; malformed/null timestamps reject rather than invent observation time. Readable pendingBuffer is a defensive snapshot.

Stop closes producer admission, fences interval generations and retains an admitted request until it settles. It drains queued prefixes until acknowledgment or first failure, returning `{success, acknowledged, pending}` honestly. Failed shutdown retains rows in the same object for manual retry or explicit restart; process exit still loses volatile memory. Restart waits for the current shutdown to settle. Acknowledged full batches can schedule a fenced follow-up; failures do not immediately spin retries.

Default configured client lookup is lazy, preserving the application client on an actual default write without booting unrelated API/provider dependencies in injected native tests. The exported class has no mounted producer found in this checkout. Whole API/bootstrap/GPS consumer delivery and actual database row durability are not claimed.
