# Native packing certificates

The existing two-argument `evaluatePackingAVX` uses default `PackingLimits`. The three-argument overload permits smaller positive limits. Results add a `PackingStatus`: `Packed`, `Infeasible`, `InvalidInput` or `ResourceLimit`. The original fields and source entry point remain; clients must rebuild against the updated struct layout. A false result carries no placement map. `packedCount` on geometric/work failure counts previously accepted boxes, not a usable partial certificate; invalid geometry returns zero.

All bed/cargo dimensions must be finite and strictly positive. All rows are admitted before placement. Computation uses double for volume ratios over the full finite binary32 range, and bounds use paired subtraction comparisons rather than an absolute physical tolerance or endpoint addition. This catches both oversized small-scale geometry and a positive offset absorbed when added to a very large span. Public float coordinates round outward; actual exported geometry must fit and be disjoint. Arithmetic roundoff in certified volume accumulation is clamped only in the final utilization presentation, never in the geometry.

The same six orientations and ascending mixed-coordinate Cartesian order are visited lazily. Only the three coordinate lists are allocated; the Cartesian product is not materialized. Limits apply to the complete call: at most128 boxes,1,000,000 coordinate products per box,1,000,000 attempted candidates,10,000,000 overlap checks. These are hard library ceilings; the overload can lower each. Products are checked using division before multiplication, and loops stop before the next over-budget check. Exhaustion is distinct from geometric infeasibility. Empty cargo in a valid bed is a zero-utilization successful certificate.

This is a bounded greedy search. A rejection does not prove an arrangement is impossible, and representable public coordinates may reject a packing that requires finer coordinates. No optimality, order independence, real cargo clearance, calibrated units, axle/stability/loading or vehicle-quality guarantee is claimed. The inherited AVX method name does not imply this scalar geometry path uses SIMD. Callers must not mutate input vectors concurrently; no cross-thread/process input ownership is promised.

Focused verification compiles only the packing library and its two native test executables. It does not claim the separate HTTP vector-search server or Docker image builds. Both GCC and Clang Linux runners use warnings-as-errors plus address/undefined sanitizers; Debug retains the original assertions.
