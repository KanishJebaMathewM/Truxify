# Native NeRF camera-to-image execution

Image admission accepts the camera's flat [pixels,3] or the existing batched [1,pixels,3] Torch geometry. Complete private ray copies are checked for matching raster, model dtype/device, finite nonzero directions and representable sampled/Fourier endpoints before the first native query. Copying does not promise an atomic snapshot during unsynchronized external writes.

Image inference uses the existing render_rays equations in ordered chunks of at most16384 sampled points, with each chunk's intermediates retired before the next query. RGB and depth are copied into image output storage. The standalone API retains weights and alpha by default, including the existing video method. Explicit include_samples=False avoids retaining sample fields for the HTTP endpoints that only consume JPEG/depth; it does not change volume arithmetic or direct render_rays gradients. Model parameters/configuration layout and checkpoint keys are unchanged.

Admission limits:120 poses, each axis1..1024, at most1048576pixels per image,1..256samples,128000000total pose-pixel-samples per scene and8388608retained sample slots per standalone image when sample fields are requested. The valid default30poses×256×256×64 remains admitted. Whole HTTP scene policy is checked before creating poses/rays. Invalid counts, raster/work or radius/height return422. Existing native worker operation ownership and cancellation lifetime remain.

These are query/work/output bounds, not a universal byte/RSS or latency guarantee. Complete rays, retained image/video outputs, model width/dtype, allocator caching and concurrent service activity still consume memory. Standalone video retains its requested sample outputs; HTTP retains all JPEG/depth frames until the response. No scheduler fairness, physical rendering quality, learned-scene calibration, deployment or provider/hardware claim. Direct model mutation/training still needs its existing operation owner; chunking introduces no separate parameter synchronization.

Native verification compares chunked images against full real Torch volume rendering in float32/64, singleton and multiple samples; preserves weights/alpha and video controls; observes actual native query sizes and weak-reference retirement; mutates caller arrays after admission; rejects late invalid rows before any query; verifies actual camera/JPEG/depth ASGI responses and pre-allocation scene refusal. Existing ray learning, worker exclusion/cancellation, camera geometry, volume and checkpoint consumers remain. Two old worker checks intentionally expected the previously broken flat-camera500; only that obsolete expectation is changed to200, retaining all native exclusion assertions. One existing AnyIO deprecation remains. No deselections.
