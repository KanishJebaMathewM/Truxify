# Native return-load quote and scoring contract

Run `NODE_ENV=production LOG_LEVEL=fatal node --test backend/api/test/native/profitabilityScorer.node.mjs` with Node24/Pino10.3.1. Tests use actual scorer/native spherical geometry. The charge fixtures were generated independently using Python3 `Fraction.from_float`, exact rational multiplication and nearest-integer rounding with halves upward (seed17769). No financial/provider/database service is called.

Admission owns complete corridor and at most1000identified candidate loads before scoring. Coordinates must be finite/geographic; canonical finite decimal coordinate strings from database results are supported. Quotes are required, nonnegative safe integer paisa (numeric, BigInt or canonical integer strings). Missing/nonfinite/fractional/unsafe quotes reject the whole batch, rather than silently dispatch an invented500000paisa offer. Zero quotes are valid but unprofitable and omitted. Optional metadata is admitted as bounded primitives; malformed later candidates cause rejection before any result returns.

Detour ratio policy is finite in [0,1]. Zero means no incremental detour. Zero direct-distance corridors permit only zero incremental distance. Integer fuel-rate zero is honored; the existing200paisa/km toll proxy remains. Positive supplied direct distance is used as before; absent/zero direct distance falls back to native spherical origin/destination distance. No claim is made that straight pickup/drop segments represent OSRM road lengths or calibrated fuel/toll rates.

Charges multiply the exact admitted binary64 incremental-distance value by integer rate, rounding once to paisa. Exact BigInt rational comparisons also admit detour ratios and rank affinity before presentation rounding. Genuine ties preserve source order. Three new exact safe integer fields (`extraFuelPaisa`, `extraTollPaisa`, `netIncrementalPayoutPaisa`) complement existing financial keys; use paisa for accounting. Existing INR numbers and one/three-decimal distance/affinity values remain display approximations and are not lossless extreme-value money serialization.

Any native geometry failure is rejected rather than producing ranked NaN. Separate geofence repair17768 fixes the current antipodal helper regression; these tests support either that repaired finite distance or current-main rejection. Whole DriverDispatchPipeline/provider/database/notification bootstrap and financial calibration are outside scope. The scorer operates synchronously with private read-only configuration and independently owned output primitives; it does not establish distributed booking reservations or payment execution.
