# Native geofence observation ownership

Run `NODE_ENV=production LOG_LEVEL=fatal node --test backend/api/test/native/geofenceEvaluator.node.mjs` with Node24/Pino10.3.1. The isolated Linux workflow does not boot the API, Redis, Supabase or GPS devices. Tests use actual GeofenceEvaluator, exported distance and ProfitabilityScorer with independent unit-vector/cross-product angular-distance expectations (600 seeded pairs), not mocked numerical operations.

The exported distance admits finite geographic numbers before calculating spherical Haversine distance. Its [0,1] roundoff domain is clamped at antipodes, and equivalent exact dateline/pole positions have zero distance. This is spherical distance, not an ellipsoidal survey or road-routing distance. Invalid coordinates now throw rather than propagate NaN; this also changes the routing scorer's invalid-input behavior from NaN output to rejection. Native valid/antipodal routing output is tested; no financial calibration claim is made.

Registrations admit and copy geographic coordinates, bounded identifiers/text and radius in [0,pi*EarthRadius]. An omitted radius defaults to500metres; explicit zero remains zero. IDs accept nonblank strings up to256characters without surrounding whitespace, or nonnegative safe integers (including zero). Names/type strings are bounded at512/64characters. Legacy event keys and ENTER/EXIT behavior remain. Each complete evaluation prepares all distances, events and new membership before one publication. Invalid coordinates never fabricate an EXIT or allocate a new trip. One evaluation shares one native timestamp across its events.

Owned maps/sets are private. `geofences` and `tripStates` retain readable Map/Set shapes as defensive snapshots; mutating those views no longer reconfigures the evaluator. Use `registerGeofence`, `removeGeofence`, and `clearTrip` deliberately. Configuration removal clears its membership without fabricating an observation-driven EXIT. Replacement at capacity remains allowed. Limits default to1024fences/10000trips and are configurable positive integers up to1,000,000; exhaustion rejects a new owner rather than evicting a live record. Clearing completed trips/removing unused fences recovers capacity.

This provides synchronous process-local observation ownership, not persistent event delivery, distributed ordering, spatial indexing, calibrated GPS accuracy or delivery authorization. Whole-ingestion bootstrap is not tested. The previous scalar filter and other delivery geofence routers are outside this change.
